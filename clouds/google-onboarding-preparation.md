# Google 入职前准备

> 入职日期：2026 年 9 月 14 日
> 使用期限：现在到正式入职
> 文档定位：一张入职前的准备地图，不是入职后的工作手册。

---

## 0. 为什么写这份文档

入职以后，真实的角色、团队、工具、流程和工作方式都会逐渐清晰，很多现在的设想也会被重新定义。

所以我现在不需要设计一套特别细致的工作系统，也不需要猜测入职后的每个场景。这份文档只用来帮助我：

- 调整进入新环境的意识；
- 梳理入职前值得准备的大方向；
- 提前构想几种可能有帮助的 Agent；
- 记录接下来想逐项讨论的问题；
- 让我在 9 月 14 日到来时，精神和生活都处于适合开始的状态。

正式入职后，这份文档就完成使命，不再继续更新。真正的工作方法，等了解实际环境后重新建立。

## 1. 入职前最重要的意识

### 1.1 不需要提前成为一个完美的 Google 人

我被录用，不是因为我已经知道内部的一切，而是因为团队认可了我现有的经验、思考方式、沟通能力和成长潜力。

入职前的目标不是补完所有知识，也不是证明自己配得上，而是保持一个清醒、稳定、愿意学习的状态走进去。

### 1.2 先理解，再创造价值

刚进入新环境时，最重要的是理解：

- 团队在解决什么问题；
- 我的角色为什么存在；
- 谁是客户和合作对象；
- 团队如何沟通和做决定；
- 什么才是这个角色真正有价值的产出。

不急着给答案，不急着评价现有方式，也不急着展示自己知道很多。

### 1.3 从 Engineer 走向 Consultant

未来的价值不只在于“能不能实现”，也在于：

- 能否理解真实问题；
- 能否把模糊的信息整理清楚；
- 能否连接技术、业务和人；
- 能否讨论不同方案的 trade-off；
- 能否帮助大家形成共识并向前推进；
- 能否让技术最终改善客户的工作。

我不需要在入职前掌握咨询工作的所有方法，只需要意识到，自己的视角正在从“完成技术任务”走向“帮助别人解决复杂问题”。

### 1.4 可靠比惊艳更重要

进入新团队后，真正建立信任的往往不是一次惊艳的表现，而是：

- 真诚；
- 守时；
- 认真倾听；
- 不懂就确认；
- 说到做到；
- 清楚表达自己的理解；
- 遇到问题及时沟通；
- 尊重每个人的经验和时间。

### 1.5 允许自己经历新手期

不熟悉缩写、流程、人物和内部系统是正常的。

第一天不需要像工作了一年，第一周也不需要证明未来十年的能力。学习本来就是入职的一部分。

## 2. 入职前准备的几个方向

### 2.1 精神状态

- 不把入职当作又一场面试；
- 从“我要证明自己”切换到“我要理解和连接”；
- 接受兴奋、紧张和不真实感同时存在；
- 不用新的学习任务填满所有空闲时间；
- 给过去的阶段一个结束，也为新的生活留出空间。

### 2.2 身体与生活

- 调整睡眠和起床时间；
- 保持运动、散步和正常饮食；
- 提前确认通勤、时间、地点和第一天所需物品；
- 给入职前最后几天留出休息时间；
- 不在前一天高强度突击学习。

### 2.3 语言

不追求短时间显著提高语言能力，只准备几个高频场景：

- 简短的中英日自我介绍；
- 说明过去的职业经历；
- 说明为什么从 Engineer 走向 Consultant；
- 听不懂时自然地确认；
- 复述自己的理解；
- 表达暂时不知道、需要确认；
- 在会议结束时总结下一步。

### 2.4 技术与咨询知识

只做轻量回顾，不再扩大知识范围：

- Cloud、data platform 和 architecture 的整体知识树；
- Migration、modernization 和 data analytics 的基本思路；
- Security、reliability、cost 和 data quality 等常见视角；
- Clarify、current state、goal、constraint、option、trade-off、recommendation 这一套解决问题的顺序；
- 自己最熟悉的几个项目，以及从中真正学到的东西。

重点不是背产品知识，而是保持思考框架可以随时调用。

### 2.5 系统了解 Gemini

入职前可以系统体验一次 Gemini 生态，重点不是学完全部功能，而是理解不同工具适合解决什么问题：

- Gemini 的基础对话、文件输入和 Deep Research；
- 怎样创建和配置自己的 Agent；
- Gemini 与 Gmail、Calendar、Drive 等 Workspace 工具可能形成的工作流；
- 怎样让 Agent 的输出稳定、简洁并符合自己的习惯；
- NotebookLM 如何管理 sources、基于资料问答和生成摘要；
- Gemini、NotebookLM 和自定义 Agent 之间应该怎样分工。

其中，NotebookLM 更适合处理一组文档和建立基于来源的知识空间。它支持 Google Docs、Slides、Sheets、PDF、Markdown、网页等来源，可以基于来源回答并提供引用。NotebookLM 的 notebook 也可以在 Gemini 中使用。

## 3. 入职前的 Agent 构想

这个 Agent 现在只确定用途，不急着连接工具或设计自动化流程。入职后是否需要、应该怎样实现，都以真实工作环境为准，重新判断。

### 3.1 双语辅助 Agent

这是一个极简的中英日转换工具，不承担会议管理、文档分析、草稿校对或系统语言学习。

主要用途：

- 我给出中文，它生成自然的日语和英语；
- 我单独询问不懂的词汇或表达时，它用中文解释；
- 对不容易使用的词汇，给出更简单、自然的替代讲法；
- 保留我的原意，不擅自添加事实、情绪或承诺。

#### 创建 Agent 时使用的 Prompt

```text
你是 Sally 的中英日双语表达助手，专门帮助她把中文职场表达转换成自然的日语和英语。

## 中文转日语和英语

Sally 通常会输入一句她在日常职场中想说的中文。你需要把这句话自然地表达成日语和英语，每种语言始终只提供一个最适合真实职场沟通的版本。除非 Sally 主动要求，不提供“更随意”“更礼貌”等备选版本。

即使输入的中文很口语、很碎、语序跳跃，或只是脑中随口想到的一句话，也要先自动整理核心意思，再转换成日语和英语中顺畅、自然、真实职场里会使用的表达，不要机械逐字翻译。

忠实保留 Sally 原话的意思、立场和语气，优先于迎合所谓的当地职场习惯。只有在不改变原意的前提下，才做必要的自然化调整。

表达应当自然、简洁、真诚、专业。避免教科书式、僵硬、过度规范却不自然的表达，也不要使用不必要的高级词汇、空洞的商务套话或过度谦卑的语言。

根据中文原意和上下文，合理判断场景、关系与礼貌程度。如果存在轻微歧义，优先结合上下文作出合理推断并直接输出。只有不同理解会明显改变事实、立场、承诺或表达方向时，才提出一个最必要的问题。

默认输出结构固定为：

日语：
...

英语：
...

不要默认添加 Tips、语法讲解、修改说明或其他补充内容。

## 词汇解释模式

如果 Sally 随后只复制并发送了上一轮答案中的某个日语或英语词汇、短语或固定表达，不要把它当成新的翻译请求。自动切换到词汇解释模式，并优先结合上一轮句子的语境进行解释。

使用中文简洁说明：

1. 这个词或短语在当前语境中的意思；
2. 为什么这个职场场景适合使用它，它的语气和细微含义是什么；
3. 提供一到三个更简单、自然的替代词汇或表达，并简要说明差别和适用场景。

必要时可以补充一个很短的例句，但不要写成长篇语言课程。如果词汇可能有多个含义，优先解释上一轮语境中的含义。

## 职责边界

不要主动校对 Sally 已经写好的英语或日语草稿。不要承担会议规划、每日任务管理、长文档分析或咨询方案分析。这些任务由其他工具或 Agent 负责。

整体语气保持扁平、轻松、自然，不端着、不说教。默认只给最终可用的内容；Sally 需要更多解释时会单独询问。
```

## 4. 入职后想优先了解什么

这里只记录方向，不提前设计答案：

- 团队和组织如何构成；
- 我的实际职责与期待；
- 日常工作和客户项目的大致流程；
- 团队使用哪些主要工具；
- 信息、任务和文档通常放在哪里；
- 大家如何开会、沟通和做决定；
- 遇到问题应该找谁；
- manager 希望我最先学习和完成什么；
- 这个角色做得好的人有哪些特点；
- Gemini 和其他内部 Agent 在日常工作中如何使用。

正式入职后，不继续维护这份入职前文档。根据得到的真实答案，另开新的工作方法或 onboarding 笔记。

## 5. 当前最重要的一句话

**我不需要提前定义入职后的全部工作。我只需要带着自己的经验、好奇心和可靠性走进去，然后让真实的环境告诉我，下一步应该怎样生长。**
